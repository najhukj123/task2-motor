# 平板学习与修改代码指南

## 明天怎么打开

1. 在平板浏览器登录 GitHub。
2. 打开本仓库，切换到 `tablet-study` 分支。
3. 将仓库网址中的 `github.com` 攱成 `github.dev`，进入网页版 VS Code。
4. 主要阅读和修改 `Core/Src/main.c`。
5. 每完成一个很小的修改就提交一次，提交说明写清楚“改了什么”，不要把多个目的混在一次提交里。

## 平板上适合做的工作

### 1. 讲清速度环的数据链

沿着下面的顺序阅读代码，并给每一步补充你自己的中文注释：

`TIM2 CNT` → `encoderDelta` → `actualSpeedRPM` → `Actual` → `Error0` → `ErrorInt` → `Out` → `TIM1 CCR1`

确认自己能回答：

- 为什么控制周期现在是 80 ms？
- `actualSpeedRPM = encoderDelta × 750 / 1456` 中，750 和 1456 分别来自哪里？
- 为什么 `ErrorInt` 要持续累加？
- 为什么 `Out` 必须限制在 PWM 的有效范围内？

### 2. 整理速度 PI 代码

不改变控制效果，只考虑怎样把这些职责分清楚：

- 读取编码器
- 计算速度和圈数
- 计算速度 PI
- 限制输出
- 写入 PWM
- 向 VOFA+ 发送数据

可以先写出函数草稿或注释，不必一次完成重构。

### 3. 梳理模式切换

检查串口命令进入速度模式和位置模式时，分别重置了哪些变量。重点思考：

- 为什么切换模式时需要清零积分？
- 为什么位置环需要重新记录上一次误差？
- 目标值改变时，哪些历史状态应该保留，哪些应该清零？

### 4. 设计旋钮调参映射

先不要实际调参数，只写清设计：

- 速度模式：旋钮调 `Kp` / `Ki`
- 位置模式：旋钮调 `positionKp` / `positionKd`
- 按键负责切换当前参数
- 每格变化多少、上下限多少
- VOFA+ 中需要显示哪些参数，才能知道当前调的是谁

## 暂时不要在平板上做

- 不凭感觉修改 PID 数值并认定效果变好。
- 不修改 `.ioc` 后重新生成代码。
- 不删除 CubeMX 生成文件。
- 不把未编译、未烧录的代码直接合并到 `main`。

## 回到电脑后的验证顺序

1. 拉取 `tablet-study` 分支最新代码。
2. 编译，要求 0 error；warning 逐项确认。
3. 先让电机悬空低速运行。
4. 检查目标、实际值和输出三条曲线。
5. 再进行负载与位置控制测试。
6. 验证通过后合并到 `main`。
